# 「是否计入预算」标志设计

日期：2026-09-09
状态：已确认

## 背景与目标

为记账明细增加 `countInBudget` 布尔标志，区分**日常支出**与**大额一次性支出**（如数码产品、年费）。大额支出不应挤占日常预算进度，统计页也需单独呈现大额支出金额。

## 已确认的决策

| 决策点 | 结论 |
|--------|------|
| 影响范围 | 预算进度条 + 统计页（月度/年度）都排除不计入的支出，并单独显示大额支出金额 |
| UI 范围 | 仅支出显示开关（收入与预算无关）；明细页所有支出记录显示 badge，点击可切换 |
| 默认值 | 新支出默认 `true`（计入预算） |
| 趋势图口径 | 跟随所在页面总额口径，排除不计入的支出 |
| 明细页汇总卡片 | 保持全部口径（列表显示全部记录，汇总需与列表对上） |

## 数据模型（js/storage.js）

字段：`countInBudget`，布尔值。

- `getAll()` 读取时规范化：`countInBudget: t.countInBudget !== false`（**已完成**，旧数据无需迁移）
- `add(transaction)`：接受并保存 `countInBudget`，缺省 `true`；收入记录恒存 `true`（开关对收入隐藏，标志无统计意义，统一存 `true` 保持数据整齐）
- 新增 `updateTransaction(id, patch)`：不可变方式更新单条记录（返回新数组后整体 save），供明细页切换标志
- `getMonthlyBudgetUsage(month)`：支出求和前过滤 `t.countInBudget !== false`
- `getCategoryYearUsage(category, year)`：同样过滤

## 记账页（index.html + js/pages.js）

- 备注卡片下方新增开关卡片：标题「计入预算」，说明文字「大额一次性支出可关闭」
- 仅 `currentType === 'expense'` 时显示；切到收入时隐藏
- 默认开启；每次保存成功后重置为开启
- `_saveTransaction()` 将开关状态传入 `Storage.add()`

## 明细页（js/pages.js）

- 列表仍显示全部记录，不做过滤
- **所有支出记录**的分类名右侧都显示可点击的小 badge 作为切换入口：
  - 计入预算：淡色样式「预算内」（如 `text-gray-300`）
  - 不计入预算：醒目样式「不计入」（如灰底或橙色）
  - 收入记录不显示 badge
- 点击 badge 切换计入/不计入（调用 `updateTransaction`），切换后静默刷新列表；有震动反馈（`navigator.vibrate`，与保存一致）
- 顶部收入/支出汇总卡片保持全部口径

## 统计页（js/pages.js）

### 月度

- 支出总额、分类汇总列表、每日趋势图：只统计日常支出（排除不计入的）
- 支出卡片下方新增一行：「其中大额支出（不计入预算）：¥xxx」，金额为 0 时隐藏
- 月预算、分类年预算进度条按新口径（日常支出）自动计算

### 年度

- 年度支出总额、年度分类汇总、月度趋势图：同样排除不计入的支出
- 年度支出区域同样显示年度大额支出总额，为 0 时隐藏

## 导入导出

- 导出 JSON 自然携带 `countInBudget` 字段
- 导入旧格式数据由 `getAll()` 规范化兜底，无需单独迁移逻辑

## 错误处理

- `updateTransaction` 对不存在的 id 静默返回（不抛错），调用方刷新列表即可
- 开关状态读取失败时按默认 `true` 处理（沿用 `getAll()` 的防御式风格）

## 测试

项目目前无自动化测试基础设施。验收方式：

1. 新增支出时关闭开关 → 明细页出现「不计入预算」badge → 月预算进度不包含该笔
2. 明细页点击 badge 切换 → 统计页支出总额、大额行、预算进度同步变化
3. 旧数据（无字段）读取正常，默认计入预算
4. 导出→清空→导入，标志保持
5. 收入记录不显示开关，且不受标志影响
